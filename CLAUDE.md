# gameWE AMX Mod X plugin - notes for Claude

AMX Mod X (Pawn) plugins for Half-Life 1 servers, based on the gameME plugin
2.4. One plugin per game (`addons/amxmodx/scripting/gamewe_<game>.sma`:
cstrike, dod, tfc, ns, hlmp); the shared code is in `include/gamewe_core.inc`
(server commands, chat, menu) and `include/gamewe_xstats.inc` (weaponstats).
The plugins write extra log lines for the gameWE collector (`log_message`)
and execute the collector's replies, which arrive as server commands over
RCON (`gamewe_amx_psay`, `gamewe_amx_msay`, `gamewe_amx_browse`, ... plus the
`gameme_amx_*` and `gamewe_*` spellings). No database access of its own.

Build: `make compiler` (builds amxxpc from the pinned AMX Mod X sources,
needs gcc-multilib), `make build` (warnings are errors), `make package`.
Check AMX Mod X 1.9 too: `make compiler build AMXX=1.9`.

Releases: Conventional Commits + semantic-release (`.releaserc.json`). The
GitHub workflow builds every push to `main` (package as a workflow artifact
only); `feat`/`fix`/breaking commits make semantic-release bump `VERSION`,
write `CHANGELOG.md`, commit `chore(release): vX.Y.Z [skip ci]`, tag
`vX.Y.Z` and publish the GitHub release with the package. There is no
tag-triggered workflow.

1. **Every change:** before you call a change done, commit it or open a PR,

2. **Every release, without exception (standing rule from Dennis):**
   releases are made by semantic-release in CI when `feat`, `fix` or

   `vX.Y.Z`, GitHub release). Before pushing such commits to `main`, run

3. A finding you cannot fix in scope goes into the answer with file:line,
   impact and a proposed fix. Never silence a compiler warning to get green.

## Before every commit (mandatory, standing rule from Dennis)

Run the `pre-commit-checklist` skill before every `git commit`, together
with `security-check`, also for small fixes:

1. Check `README.md` (and `INSTALLATION.md`) against the change and update
   it in the same commit.
2. Write the commit message as a Conventional Commit (`feat:`, `fix:`,
   `docs:`, ... see the `pre-commit-checklist` skill). `CHANGELOG.md` and
   the version files are generated by semantic-release; never edit them.
3. Check dependencies and toolchain for updates and *suggest* available
   updates (do not update on your own).
4. Check the licenses of third-party code and keep the license list
   complete and current.

Report the result of each step in one line in your answer.

## Invariants that must not break

- Collector commands are `register_srvcmd` only (server console / RCON),
  never `register_clcmd`/`register_concmd` or reachable by players.
- Player-controlled text (name, chat) goes into log lines only in the HL
  format `"%s<%d><%s><%s>"` exactly as the engine logs it; chat text is
  logged only when it equals a blocked trigger. Do not add new free-text
  fields from players to log lines (they would need `"` removed first).
- Every `client_print`, `client_print_color`, `show_hudmessage`,
  `log_message`, `log_amx` passes outside text as an argument to `"%s"`,
  never as the format string.
- `server_cmd`/`server_exec` only with fixed command names; nothing from
  players or the collector reaches them.
- `show_motd` only with URLs checked by `gamewe_is_valid_url` (http/https):
  any other string is read as a file of the server.
- Arguments of collector commands are parsed from `read_args` with
  `gamewe_next_token`/`gamewe_rest_of` into sized buffers; userids are
  resolved with `gamewe_player_of_userid` (in game, no bot, no HLTV).
- Buffers: every `copy`/`formatex`/`read_args`/`get_user_*` uses
  `charsmax()` of the real buffer.
